# agent 向け規則のレビュー

リポジトリの agent 向け規則を監査し，原則に反する箇所を 1 件ずつ，場所・欠陥・修正案の形で返す．
引数にパスがあればそのファイルだけ，無ければ下記の対象すべてを読む．
引数に `--fix` があれば，報告の後に修正を適用して commit する．無ければ報告だけで止まる．

## 対象

- root と各ディレクトリの `AGENTS.md`，`CLAUDE.md`
- `rules/`，`meta/`，`docs/` など規則を置くディレクトリ
- `templates/`
- `README.md`（人間向けだが，規則と食い違うことがある）
- `scripts/check*.sh`，pre-commit hook など，規則を機械的に検査するもの

読む前に `writing-for-agents` skill を読む．context pointer，情報階層，完了条件，leading word，否定，剪定の語彙で欠陥を名指す．

## 原則

監査はこの 9 つに対して行う．各原則の後に，見つけ方を書く．

1. **状態で書く**．規則は手順ではなく，agent が停止するときに成り立っているべき状態として書く．自動で行われる手順（hook が検査を実行する，など）は文章に書かない．
   - 見つけ方: 「〜する」「〜してから〜する」の連なり．hook や formatter が担う手順への言及．
2. **実行される規則だけ置く**．誰も実行しない規則（週次レビューなど），agent が判定できない起点（「セッションの終了前」）を置かない．ユーザの行為は，リポジトリが定めた少数の行為（task を作る，指定する，完了を判定する，chat で答える）に限る．
   - 見つけ方: 主語が「ユーザ」の文をすべて拾い，定めた行為の一覧と照合する．起点が「〜前に」「〜後に」の文は，その時点を agent が知れるかを問う．
3. **1 つの意味は 1 か所**．同じ規則が複数のファイルにあれば，1 か所に残して他は削除かリンクにする．
   - 見つけ方: 規則ごとに，同じ意味の文を全ファイルから grep する．
4. **使う場所に置く**．ディレクトリに結びつく規則はそのディレクトリの `AGENTS.md` と雛形に置く．常時読まれる root の `AGENTS.md` には，作業中に効く規則と参照先の表だけを置く．規則の管理方針や雛形への参照は root の `AGENTS.md` に置かない．
   - 見つけ方: root の `AGENTS.md` の各文について，「どの作業でも効くか」を問う．`rules/` の各ファイルについて，「特定のディレクトリの話か」を問う．無関係な話題が 1 ファイルに同居していないかを見る．
5. **定義する．不要な概念は消す**．状態や用語はすべて定義する．定義できない概念，使われない概念，同じ物の別名は消す．名前は日常語にし，固有名は必要なときだけ付ける．概念の名前と，それに規則を付けるかは分けて判断する．
   - 見つけ方: 定義なしに使われている語を拾う．1 つの語が 2 つの意味で使われていないか，1 つの物に 2 つの名前が無いかを見る．
6. **自然な日本語，構造化**．英語の動詞の直訳（close を「閉じる」，carry を「運ぶ」）は英語のまま書くか日本語の動詞で言い換える．見出し，箇条書き，表で，1 文 1 規則にする．
   - 見つけ方: 「閉じる」「運ぶ」「開く（open question）」「住む」「走る」など．段落に複数の規則が詰まった文．
7. **文脈に依存しない**．前のリポジトリ，移行，過去の事故に触れない．新しく入る agent が，この文書だけで迷わない．
   - 見つけ方: 固有の過去の名前，「以前は」「移行」，事故の経緯．
8. **環境の事実はコードが正**．設定値，パス，版など，コードや設定ファイルから読めるものを文書に写さない．文書には，コードに書けない事実（権限，申請の状況）だけを置く．
   - 見つけ方: 数値，パス，版番号を含む文について，出典がコードにあるかを問う．
9. **リンクと整形は道具に任せる**．ファイルへの参照は Markdown のリンクにする（リンク検査が壊れを拾う）．整形は formatter に任せ，手で揃えない．
   - 見つけ方: バッククォートで書かれたファイルパス．formatter の有無．

## 手順

1. 対象のファイルをすべて読む．
2. 原則ごとに，上の見つけ方で全ファイルを走査する．引用する箇所は grep で実在を確かめる．
3. 原則 3 と 5 は，ファイルをまたいで照合する（重複，別名，未定義）．
4. 所見を表にまとめる．列は 原則／場所（ファイルと引用）／欠陥（1 文）／修正案（短ければ置換後の文）．影響の大きい順に並べる．
5. 根本から見直すべき点（階層の逆転，無関係な話題の同居，判定できない起点）があれば，表の前に別立てで書く．
6. `--fix` があれば，表の順に修正を適用し，検査 script と formatter を通し，何を変えたかを述べる message で commit する．

## 完了条件

- 対象の全ファイルを読んだ．
- 9 つの原則すべてについて走査した．該当なしの原則も，該当なしと書く．
- 引用した箇所はすべて実在する．
- 所見ごとに修正案がある．
- `--fix` のとき，検査 script と formatter が通り，作業ツリーが clean である．
